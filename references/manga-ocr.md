# 漫画 OCR 精读

逐页识别漫画原文，提取角色的台词语感和行为细节，用于校准 SKILL.md 的表达质感和记忆基线。

## 什么时候做

- 角色台词在 Wiki 上不完整或只有语境复述，需要原文逐句校准
- 用户提供了漫画 EPUB / 图片源，希望让角色的语气贴近原作
- 记忆基线有争议，需要核对原作第几话发生了什么

Wiki 和百科够用时不做。OCR 精读耗时长，只在需要高保真语气时做。

## 工具链

| 组件 | 推荐 | 备注 |
|---|---|---|
| OCR 引擎 | PaddleOCR PP-OCRv3 | 中文漫画用 `chinese_cht`；日文原版用 manga-ocr |
| OCR 参数 | `enable_mkldnn=false` | Windows Paddle 3.3 CPU 有 bug，必须关 |
| 排序 | 按 OCR 坐标重组竖排列 → 右到左气泡 | 漫画排版特殊，不能按行读 |
| 繁转简 | OpenCC | 如果源是繁体中文 |
| 断点续跑 | 已存在的页文本跳过 | 必须，否则跑不完 |
| 守护进程 | 看门狗脚本 | OCR 卡住/死掉自动重启，完成后弹窗通知 |

## 关键参数

```python
ocr = PaddleOCR(
    use_angle_cls=True,
    lang="chinese_cht",
    enable_mkldnn=False,
    text_det_limit_side_len=1536,
    text_recognition_batch_size=8,
)
```

PP-OCRv4 漏字严重，不要换。

Windows 自带 OCR 不可用（非管理员装不了日语语言包），走 Paddle 繁中路线。

## 流程

1. **确认源格式**：EPUB 每卷约 195 页整页 JPEG；检查是否有文字层（有文字层就不需要 OCR）。
2. **跑一轮试测**：选角色首次登场的卷和页，跑 10 页看效果。确认 OCR 能识别气泡文字。
3. **全文跑批**：每卷输出一个 txt 文件（每页一行）。脚本支持断点续跑。开启看门狗守护。
4. **角色筛选**：全文跑完后，用关键词/角色名搜索该角色的台词所在页。不需要精读全部文本，只精读角色相关段落。
5. **语气蒸馏**：把角色台词按场景归类，提炼句式、高频词、口癖、情绪变化模式。与 Wiki 阶段的「表达质感」交叉比对。
6. **记忆基线校准**：用 OCR 文本核对「第 X 话发生了什么」，修正 SKILL.md 中记忆基线的时间点。
7. **关键场景亲眼看**：OCR 文本只能给语感，关键场景（角色关系转折、性格揭示）用图片查看器亲眼看漫画页面，补充视觉细节（表情、动作、构图）。

## 踩坑记录

- Paddle 3.3 Windows CPU 不开 mkldnn 会崩，开了会慢但稳
- 竖排列按行读会串行，必须按坐标重组
- 繁体识别用 `chinese_cht` 模型，不要用简体模型硬读
- OCR 会把拟声词和台词混在一起，蒸馏时人工过滤
- 跑完后的 OCR 文本按卷保存（卷01.txt ~ 卷28.txt），不要合并成一个大文件，后续检索按卷定位更方便
