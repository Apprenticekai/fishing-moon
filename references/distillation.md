# 行为蒸馏

把角色的公开资料提炼成 agent 可执行的行为系统。产出 `SKILL.md` + `manifest.json` + `references/` 研究链。

## 来源优先级

| 优先级 | 来源 | 示例 |
|---|---|---|
| 最高 | 用户提供材料 | 设定集、访谈、截图、用户精读原文 |
| 高 | 官方网站、官方角色页 | franchise 官网、游戏剧情文本 |
| 高 | Wiki 百科 | Fandom、Wikipedia、萌娘百科 |
| 中 | Bangumi、AniDB、高质量专栏 | bgm.tv、anidb.net |
| 低 | 粉丝讨论、社区解读 | 必须标注为推测 |
| 排除 | 知乎、微信公众号、百度百科 | 不可作为来源 |

重要结论至少需要两个独立来源。来源冲突时保留冲突，不要强行调和。

## 流程

1. **Source Discovery**：检索候选来源，收集别名，判断跨媒体。记录每条来源的 URL、检索日期、可信度、状态（成功/失败）。失败来源也要记录。
2. **五维研究**：设定（世界观/时间线）、性格（行为模式/压力反应）、表达（句式/词汇/口癖）、关系（重要关系模板）、名场面（至少 8 个关键场景）。每份研究文件必须标注来源和可信度。
3. **行为蒸馏**：从研究文件提炼 3-7 条核心行为模式。每条必须回答「在什么情况下 → 做什么 → 为什么」，并跨至少两个场景可复现。发展性矛盾和情境性矛盾保留，不抹平。
4. **表达质感**：从台词和原文提炼句式、高频词、禁忌词、节奏、情绪泄露方式。重点抓「她怎么说话」而非「她说过什么」。
5. **记忆基线**：与用户确认角色对话默认停在剧情哪个时间点。此时间点之前已发生的剧情算「记得」，之后算「不记得」。这条必须写死在 SKILL.md 里。
6. **用户定制**：确认用户在角色扮演中继承谁的经历。把关系模板中的「对话对象」指向用户的角色身份。
7. **质量验证**：检查行为模式数量、证据链、矛盾保留、表达质感、诚实边界、来源标注。不过关则补充研究。

## SKILL.md 必须包含

- 角色扮演规则（最高优先级）：角色视角而非上帝视角、口语而非文章、不跳出角色
- 运行核心：核心动机、默认反应、压力反应、硬约束
- 资料时间边界：检索完成日期 + 资料可能未覆盖最新内容
- 记忆基线：默认时间点 + 记得什么/不记得什么
- 身份卡：我是谁/我的世界/别人第一眼看到我/当前时间线
- 行为动态：默认状态、压力之下、面对对话对象、面对其他人、核心矛盾、低置信度行为
- 表达质感：句式、词汇、语言标志、节奏、情绪泄露
- 社会认知：默认解读、会注意到什么、会忽略什么、关系模板
- 决策逻辑：核心动机、价值优先级、硬约束
- 知识边界：我所知/我所不知/面对不知
- 行为示例：至少 3 个场景
- 诚实边界：资料覆盖范围 + 低置信度内容标注

## manifest.json 必填字段

```json
{
  "schema_version": "1.0",
  "name": "character-slug",
  "character": "角色名",
  "work": "作品名",
  "generated_at": "YYYY-MM-DD",
  "latest_source_checked_at": "YYYY-MM-DD",
  "covered_until": { "date": "YYYY-MM-DD", "description": "..." },
  "covered_media": [],
  "not_covered": [],
  "source_count": 0,
  "source_tiers": {},
  "honesty_boundary": "..."
}
```

## 绝不做

- 用萌属性标签（傲娇/病娇/天然呆）取代具体行为描述
- 编造角色在原作中没说过的话
- 在信息不足时强行生成完整人设
- 忽略资料检索日期
- 用户指出新剧情时硬拗旧设定（先承认边界，再走更新流程）
- 把单一来源的粉丝推测写成核心行为模式
